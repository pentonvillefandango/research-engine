## 4. Adjustments to the §11 build order

Step numbers are unchanged. Two things move earlier:

1. **Event and cache seams in step 2.** Step 2 introduces an `EventSink` protocol with an in-memory implementation, plus a `Cache` protocol, so search and fetch emit events and report `cache_hit` from the start. Step 4 swaps in SQLite-backed implementations behind the same interfaces.
2. **Minimal `compose.yaml` in step 2.** It contains only `searxng` and `crawl4ai`, pinned, with no published ports, and is used to record real response fixtures and run integration tests. Step 8 adds `app`, limits, hardening, the `proxy` network and Caddy.

## 5. Component design

### Search (V1-01 to V1-03)
- The `SearchProvider` adapter calls SearXNG `GET /search?format=json`. Presets in `config/intents.yaml` map each intent to engines and categories.
- **Canonical URL:** lowercase scheme and host; drop the fragment, default port and tracking params (`utm_*`, `gclid`, `fbclid`, …); sort the query; strip the trailing slash.
- **Score:** `Σ_engines 1/(60 + position)` × `(1 + 0.1 × (n_engines − 1))`. The result's `rank` follows the score.
- Each unresponsive engine produces an `unresponsive_engines` entry plus a `search.engine_failed` event. If there are fewer than `SEARCH_MIN_RESULTS` (default 10) results, retry once with the `general` preset and merge.

### Fetch (V1-04 to V1-06)
- **Static path:** a streaming httpx GET with `MAX_RESPONSE_BYTES` and a content-type allow-list (HTML, XHTML, PDF, plain text).
- PDFs (by content type or `%PDF-` magic) are parsed with pypdf, giving text plus page count.
- HTML goes through Trafilatura (markdown + metadata) for the body. extruct handles JSON-LD, microdata and OpenGraph; lxml parses `<table>` into `Table`; links come with their anchor text.
- **Escalate to Crawl4AI** when any of these hold:
  - the static fetch fails (network error, 403/429, 5xx after retry);
  - `word_count < THIN_WORD_THRESHOLD` (default 150);
  - SPA heuristics fire (an empty root mount element with heavy scripts, or a `<noscript>` "enable JavaScript" message).
- Browser HTML runs through the same table, extruct and link extractors. Markdown comes from Crawl4AI's `raw_markdown`.
- `provenance.method` is `static|browser`. `warnings[]` records the escalation reason. `quality` holds `word_count`, `text_html_ratio`, `has_title` and `escalation_reason`.
- `Provenance.content_hash` is the SHA-256 of the cleaned markdown.

### Safety and politeness (V1-11, §8)
- **SSRF guard:** resolve the host, then reject loopback, private, link-local, CGNAT, multicast, reserved and cloud-metadata ranges (v4 and v6) unless the host is in `SSRF_ALLOW_HOSTS`. Applied before the request **and on every redirect hop** (manual redirect following, max 5). The browser path pre-checks, and Crawl4AI's own guard remains on.
- **robots.txt:** fetched and cached per origin and parsed with Protego. A disallowed URL gives the typed error `robots_disallowed` (not retryable); crawl-delay is honoured.
- **Per-domain limits:** a semaphore (`DOMAIN_CONCURRENCY`, default 2) and a minimum interval (`DOMAIN_DELAY_S`, default 1.0). The User-Agent comes from config.

### Cache (V1-10)
- SQLite table keyed on `sha256(kind + normalised request)`. TTLs are `CACHE_TTL_SEARCH_S` (3600) and `CACHE_TTL_PAGE_S` (86400). `use_cache=false` bypasses reads but still writes. `meta.cache_hit` is set on a hit.

### Jobs (V1-07 to V1-09)
- A SQLite `jobs` table (WAL), using SQLModel on aiosqlite. `JOB_WORKERS` (default 2) asyncio workers claim queued jobs atomically.
- Sub-tasks run with bounded concurrency (`JOB_FETCH_CONCURRENCY`, default 5). Progress is stored as `{done, total}`.
- **Outcomes:** any sub-failure gives `partial` with `errors[]`. A total failure gives `failed`. Cancel sets the status to `cancelled` and cancels the asyncio task. Timeouts are `JOB_TIMEOUT_S` (900) and `PAGE_TIMEOUT_S` (60).
- On startup, jobs still `running` are marked `failed` with code `interrupted` and are not auto-retried.
- `?wait=N` (capped at 60) awaits an in-memory completion `asyncio.Event`.

### Events (V1-15)
- Each `Event` is written to SQLite, published on in-memory pub/sub (a bounded queue per subscriber, dropping the oldest), and logged via structlog JSON to stdout.
- `kind` is an enum (`search.*`, `fetch.*`, `job.*`, `cache.*`, `robots.*`, `system.*`). Retention is `EVENT_RETENTION_DAYS` (30).

### API
- Every response is `Envelope[T]` with `meta{request_id, schema_version, took_ms, cache_hit}`. Errors use the proper HTTP status plus an envelope with typed `errors[]`.
- **Routes:** `POST /v1/search`, `POST /v1/fetch`, `POST /v1/fetch/batch` (≤50 URLs, returns a job), `POST /v1/search_read` (returns a job), `GET /v1/jobs/{id}?wait=`, `DELETE /v1/jobs/{id}`, `GET /v1/schemas[/{name}]`, `GET /v1/engines`, `GET /health`, `GET /version`. Every route has OpenAPI examples.
- **Auth middleware** covers `/v1/*`, `/mcp` and the GUI. The API key is compared with `hmac.compare_digest`. `/health`, `/version`, `/login` and static assets are open.

### MCP (V1-12)
- `MCPServer` is mounted at `/mcp` via `streamable_http_app()`. The FastAPI lifespan runs `session_manager.run()`, and `transport_security.allowed_hosts` is built from `SITE_HOST` plus `localhost`.
- The tools `web_search`, `web_fetch`, `search_and_read` and `get_job` return Pydantic models (so they have an output schema and structured content) and call the same service layer as REST.

### Typed client (V1-13)
- `ResearchEngineClient` is async, built on httpx, and returns the shared models. It offers `wait_for_job()` and typed exceptions built from `ErrorDetail`.

### GUI (V1-16, V1-17, V1-21)
- Jinja2 with **vendored** htmx 2.0.11 and htmx-ext-sse 2.2.4. Live updates use FastAPI-native SSE.
- **Pages:**
  - `/login`.
  - `/`, the dashboard: a "Now" panel, a live event log (filters, pause, auto-scroll) and a health strip.
  - `/jobs/{id}`: request, event timeline, a collapsible JSON viewer and rendered markdown.
  - `/try`, the test console: Search, Fetch and Search-and-read forms calling the public REST API with the session cookie; demos from `config/demos.yaml`; results as cards, rendered markdown with tables and JSON-LD, and the raw envelope; "Copy as" curl, Python client or MCP; a run history with re-run.
- Untrusted markdown is rendered to HTML and then sanitised with `nh3` (an allow-list) before display.

## 6. Testing

- TDD per step. Unit tests are offline: respx for httpx, plus recorded fixtures (real SearXNG JSON, real Crawl4AI `/crawl` output, a static article, a JS app, a PDF, and a page with JSON-LD and tables).
- A schema test validates every response model against its exported JSON Schema; CI fails if `schemas/` is stale.
- Integration tests (`-m integration`) run against the Compose stack and cover the V1 acceptance checks.
- The model-free MCP test uses `openai-agents`' `MCPServerStreamableHttp` (B6).
- **Tooling:**
  - ruff with an explicit `select`.
  - pyright: strict on `research_engine_client`, standard elsewhere.
  - pytest-asyncio with `asyncio_mode = "auto"`.
  - Coverage target about 85% on `research_engine`; a guide, not a gate.

## 7. Deployment and operations

- **Compose:**
  - `name: research-engine`; pinned images; healthchecks; `restart: unless-stopped`.
  - Limits and log rotation on every service, configured from `.env`.
  - `app` and `crawl4ai` run non-root with `no-new-privileges`, `cap_drop: ALL`, and a read-only filesystem where possible.
  - `shm_size: 1gb` on `crawl4ai` only. No published ports except an optional `APP_PORT`.
  - Only `app` joins the external `proxy` network.
  - Secrets (`API_KEY`, `SEARXNG_SECRET`, `CRAWL4AI_API_TOKEN`) come from `.env` only. Stubbed `vpn` and `ollama` profiles are left commented out for V2.
- **Shared Caddy** (`deploy/caddy/` → `/opt/caddy/`): `tls internal`, `import sites/*.caddy`, and an index page. The site file proxies `{$SITE_HOST}` to `app:8000`, uses `remote_ip {$LAB_SUBNET}` and `flush_interval -1`.
- **Ops:**
  - `ops/*.sh` (bash, `set -euo pipefail`) wrapped by the `Makefile`. Each prints a single JSON summary line at the end and exits non-zero on failure.
  - `deploy` refuses a dirty tree, appends to `deploys.jsonl` and auto-rolls back on smoke failure via a `rollback/<ts>` branch.
  - `backup` uses SQLite's online backup API inside `app`. `bootstrap` installs a systemd backup timer and is run by the owner because it needs sudo.
- **Guardrails:** project `.claude/settings.json` makes `make deploy|rollback|restore|bootstrap` always ask, and denies `docker compose down -v`, `docker volume rm` and `git push --force`.
